Vibecoding taster 04 / NN

How to work today

Four rules for today.

None of these are about code. All of them are about not getting stuck.

  • 01

    Every prompt on these slides copies on click

    Click any prompt and it's on your clipboard, ready to paste. You'll see Copied appear in the corner.

  • 02

    Ask for one thing at a time

    If you stack five changes into a sentence you'll get four of them and no idea which one it dropped.

  • 03

    If it goes wrong, start again

    Sometimes the preview won't load, or the app drifts somewhere you didn't want. That's the tool having a moment, not you. Open a new chat, paste your first prompt again, and you'll get there faster than by arguing it back.

  • 04

    Use the tools you have

    Got a question you don't know the answer to? Have an idea but not sure if it'll work? Open a new Gemini chat and ask it.

Vibecoding taster · Part 2 09 / NN

Part 2 · What an API is

An API is a tap you can plumb directly into your app. You send a request, and structured data comes back.

Your app asks

It sends a question to a service on the internet. "What's the weather in Leeds tomorrow?"

The API answers

In data built for software, not people: a temperature, a chance of rain, a wind speed. Your app turns that into something you can read.

You don't do the plumbing

Name the API in your prompt and Gemini writes the code that asks and reads the answer. Your job is to pick a good source, and to check what comes out.

All twelve you'll choose from are free and need no sign-up. Out in the wild, some APIs want a key, which works like a password and is tied to you. Never paste a key into Gemini.

Or go and find your own.

The twelve will keep anyone busy. But if there's a subject you actually care about, this will go and find you something to build with. Then build it like the others, with its link at the end of your prompt.

Use a new chat

This one isn't a build, it's a question. Open a fresh Gemini chat and ask it there. Canvas is off by default in a new chat, so you'll get an answer rather than an app, and whatever you've already built stays untouched in the other one.

Ask this in a new chat

Give me three completely free, open APIs that need NO API key, work from a browser, and return data about [TOPIC]. For each, give me a working example link, explain in plain English what data it returns, and suggest three realistic things I could build with it.

Vibecoding taster · Part 3 15 / NN

Part 3 · Step one · Combining APIs

Try combining two or more APIs.

Most useful apps draw on more than one source. You don't have to join them up yourself: name both in your prompt and say what you want at the end.

  1. You type

    N1 9GU

    A postcode

  2. Postcodes.io answers

    51.53, −0.12

    Where that postcode is on the map

  3. Open-Meteo answers

    Tomorrow's weather

    Temperature, rain and wind for that spot

Try it in a new chat

I want to use Postcodes.io and the Open-Meteo API to build an app where I type a postcode and it tells me tomorrow's weather there. Tell me when it's loading and if there's an error.

API links: https://api.postcodes.io/postcodes/N19GU and https://api.open-meteo.com/v1/forecast?latitude=51.5&longitude=-0.1

Neither could do it alone. Open-Meteo doesn't understand postcodes, and Postcodes.io knows nothing about weather. The Who's my MP? build does the same trick.

Part 3 · Step two · Add the brain

Now build a model in.

Until now the app has only fetched facts. This puts an LLM inside it, so it can transform the data into something else. Canvas can already use Gemini in this way. We just have to ask.

  1. The API answers

    The facts

    Tomorrow's temperature, rain and wind

  2. Gemini reads them

    And makes something new

    Whatever you ask it for

  3. From the same facts, any of these

    • WordsA limerick about tomorrow's weather
    • A pictureThe place, drawn in that weather
    • SoundThe forecast read aloud, for anyone who can't see the screen
    • Advice · try it belowWhat to wear, in one line
    • Another languageThe forecast in Spanish, for a colleague in Madrid
    • A warningA heads-up for the office if it'll be wet

Add this to your weather app, or change it to suit yours

Add a button labelled "What should I wear?". When clicked, it should write a one-line suggestion based on the forecast data. Show the answer under the forecast.

Vibecoding taster · Part 3 17 / NN

Part 3 · Before anyone else uses it

If it's wrong, it's yours.

Anyone who opens your app will assume it's right. So check the whole thing, not just the clever part. The more a step changes the data, the harder you check it.

  1. Check it

    The data

    A trusted API can still be out of date, or answer a slightly different question from the one you meant.

  2. Check it harder

    Your app

    The code can pick the wrong Newcastle, mix up units or quietly drop a result, and still look finished.

  3. Check it every time

    What the model wrote

    It can invent things, smooth over detail and sound just as sure either way. Read it against the facts it was given.

Try it with things you know well. Then show it to someone who knows more than you.

Vibecoding taster 20 / NN

Before you go · What to take away

Four things worth keeping.

  1. 01
    Live data is the step that turns a toy into something usefulEverything before that is a nice demo
  2. 02
    Everything is a data problemYour app is only as good as its data. Don't let it fall back on training data. Direct it, then check it
  3. 03
    The real leap is putting facts and a model togetherReliable data from an API, plus a model to transform it. That pattern works for almost any task in any department
  4. 04
    LLMs think outside the box because they don't have a conception of the boxLike King Midas, be careful what you wish for. The less specific you are, the more potential for the output to (unpleasantly) surprise you
